# Prompt 版本管理规则

## 1. 目标

使每次 Prompt 变更都能回溯、复现、对比和回滚，避免出现“版本号没变，Prompt 内容已变”或“新评测覆盖旧结果”的情况。

## 2. 版本号格式

统一使用：

```text
{module}-v{MAJOR}.{MINOR}.{PATCH}
```

示例：

- `emotion-v1.2.0`
- `intent-v1.1.0`
- `annotation-v1.1.0`

其中：

- `module`：Prompt 所属任务，如 `emotion`、`intent`、`annotation`。
- `MAJOR`：任务定义、标签体系或输出 Schema 发生不兼容变更。
- `MINOR`：在任务和 Schema 兼容的前提下，修改分类规则、优先级、边界、示例或证据要求，可能改变模型预测。
- `PATCH`：只修正错别字、排版、注释或不改变语义的表达。

> 本规则从文档创建后开始执行，不追溯重命名已存在的 Prompt 和评测文件。例如，现有 `intent-v1.1.0` 与旧版存在 Evidence Schema 变化，但为保持历史结果可回溯，保留原版本号；后续再发生不兼容变更时必须升级 `MAJOR`。

### 升级示例

| 变更 | 应升级为 |
|---|---|
| 情绪从 5 类改为 4 类 | 下一个 `MAJOR` |
| Evidence 从字符串数组改为 `{role, text}` 对象 | 下一个 `MAJOR` |
| 增加“拒收流程优先于后续补发” | 下一个 `MINOR` |
| 增加边界样例或修改置信度规则 | 下一个 `MINOR` |
| 只修正 Prompt 中的错别字 | 下一个 `PATCH` |

如无法确定是 `MINOR` 还是 `PATCH`，只要变更可能影响模型输出，就按 `MINOR` 处理。

## 3. 文件组织

每个 Agent 使用以下结构：

```text
{agent_module}/
├── prompts.py                  # 当前生效版本
└── prompt_versions/
    ├── {module}_v1_0_0.py     # 历史快照，只读
    └── {module}_v1_1_0.py
```

维护要求：

1. `prompts.py` 只保存当前生效版本。
2. 修改前，必须先把当前 Prompt 完整复制到 `prompt_versions/`。
3. 历史快照必须保留 Prompt 原文、版本常量和输入组装方法，不得只保留摘要。
4. 历史快照创建后视为只读，不得在原文上继续修改。
5. 历史 Prompt 如果当时没有存档，不得把后续还原版冒充为原版；必须明确标记“还原版，不保证逐字一致”。
6. `PROMPT_VERSION` 或对应版本常量必须与文件内容和存档文件名一致。

## 4. 变更流程

每次修改 Prompt 必须按以下顺序执行：

1. **明确问题**：列出要修复的错误样本、对话证据和预期行为。
2. **提交方案**：向用户展示拟修改的规则、可能影响的相邻类别和建议版本号，获得许可后再修改。
3. **锁定基线**：记录旧版 Prompt、模型、模型参数、评测集版本和基线指标。
4. **存档旧版**：在改动 `prompts.py` 前生成不可变历史快照。
5. **升级版本**：按 `MAJOR.MINOR.PATCH` 规则修改版本号，不得沿用旧版本号。
6. **最小改动**：只修复本轮已确认问题，不同时改动无关规则。
7. **静态校验**：检查标签枚举、Schema、版本常量、Prompt 输出示例和前后端类型是否一致。
8. **固定条件评测**：使用与基线相同的模型、参数、Ground truth 和样本过滤条件重新评测。
9. **对比与审核**：除总准确率外，必须比较分类指标、混淆矩阵、修正样本、新增错误、失败数和重试数。
10. **保留结果**：新评测使用新文件名，不覆盖旧版结果。

## 5. 评测文件命名

评测结果文件名必须至少包含：

```text
{task}_{prompt_version}_{model}_{dataset_or_filter}_{YYYYMMDD}.{jsonl|json|md}
```

示例：

```text
ticket_intent_eval_intent-v1.1.0_qwen3.6-flash_after_conversation_ticket_only_20260820.jsonl
```

每条评测记录也必须写入：

- `prompt_version`
- `model`（或在同一评测文件的元数据中唯一声明）
- Ground truth
- 模型预测
- 置信度
- 实际尝试次数
- 错误信息（如有）

如目标文件已存在，应停止并使用新文件名，不得默认覆盖。

## 6. 可比性规则

1. 对比 Prompt 时，模型、思考模式、结构化输出方式、温度、重试次数、上下文截取规则应保持一致。
2. 不得在同一轮对比中同时修改 Prompt 和 Ground truth；如 Ground truth 必须调整，应对数据集单独版本化并重新建立基线。
3. 样本过滤条件必须写入评测汇总，例如“只保留会话后创建工单的会话”。
4. 如模型或数据集发生变化，不得将指标变化全部归因于 Prompt。
5. 评测失败样本必须计入总数，不得删除失败样本来提高指标。

## 7. 发布与回滚

- 只有在静态校验和用户要求的评测通过后，才将新 Prompt 视为可接入主流程的版本。
- 发布时应确认 Agent 返回值、评测结果和前端展示中的 `prompt_version` 一致。
- 回滚时通过历史快照恢复一个已评测版本，不得修改历史快照的内容。
- 回滚后仍要执行基本校验，并明确记录当前生效版本。

## 8. 每次变更的交付清单

- [ ] 已获得用户对 Prompt 变更方案的许可
- [ ] 已记录旧版基线指标
- [ ] 已完整存档旧 Prompt
- [ ] 已正确升级版本号
- [ ] 已同步 Schema、示例和类型定义
- [ ] 已在固定条件下评测
- [ ] 已比较修正样本和新增错误
- [ ] 已保留新旧评测结果
- [ ] 已生成完整错误会话审核清单
- [ ] 已确认主流程当前生效的 Prompt 版本
